# Database And Resources

## FASTA composition

Before execution, record:

- sequence count and total residues
- organisms/strains included
- reviewed/unreviewed sources
- contaminant entries
- duplicate accessions and duplicate sequences
- whether decoys are already present or generated by TopPIC

Do not reduce a pan-proteome without scientific justification. A large database can be
intentional and required by the experiment.

## Obtaining a FASTA

Use the FASTA already staged with the Run or workspace when one is present. An
existing database is a scientific decision (composition, decoys, isoforms), not
a gap to fill, and re-fetching it silently changes the search space — fetch only
when no FASTA exists. When you must fetch, take the required accession set from
the source table and request it in one stream call:

```text
https://rest.uniprot.org/uniprotkb/stream?query=accession_id:ACC1+OR+accession_id:ACC2&format=fasta
```

Strip the `sp|ACC|NAME` decoration before querying, and verify the returned
record count matches the accession count: a query that matches nothing returns a
valid, empty FASTA rather than an error. Record the source, access date, and the
accession list in the Run — a fetched database is a staged input with
provenance, not a silent default. A single entry is also available from
`tdease.uniprot.get` with `format: fasta` (locally cached).

## Indexing decisions

Native TopPIC indexes can be much larger than the FASTA. Estimate against Backend free
storage and stop a probe before it threatens the service. An "index is in use" message
can mean concurrent writers, a stale process, invalid FASTA records, or a previous
partial index; establish which one before deleting anything.

Lookup-table mode changes E-value computation and is not a neutral resource switch.
Use it only when scientifically acceptable and record it as a method choice.

## Scheduling

- One Backend deployment executes one Run at a time.
- Within a Run, serialize TopPIC jobs sharing a database/index.
- Give each serialized TopPIC job the declared Run core budget.
- TopFD may also claim the full budget when memory-intensive.
- Lightweight conversion jobs may run concurrently only within the global budget and
  process isolation policy.
- Reserve service capacity with CPU affinity and reduced scientific-process priority.

For a 32-thread host, a 28-core scientific budget leaves four logical CPUs for the
Backend, Client, filesystem, and operating system. Treat this as deployment policy,
not a hardcoded TopPIC default.

## Safe probe limits

When behavior is unknown, use one input and enforce:

- wall-clock timeout
- disk growth ceiling
- memory ceiling
- process-tree cancellation
- isolated temporary directory
- exact executable version and command capture

Do not launch a second index/search probe against the same output directory.
